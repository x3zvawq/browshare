# Security policy

## 支持范围

安全修复优先覆盖最新发布版本。尚未发布的开发分支不承诺稳定兼容，但仍接受可验证的安全报告。

## 私密报告漏洞

请使用 [BrowShare 私密漏洞报告](https://github.com/x3zvawq/browshare/security/advisories/new)，不要在公开 Issue 中披露可利用细节。仓库的私密漏洞报告功能已于 2026-09-08 开启并通过 API 读回确认；报告者需要登录 GitHub。未提交测试漏洞报告或公开安全公告。

报告应包含：

- 受影响组件和版本。
- 部署前提与攻击者所需权限。
- 最小复现步骤。
- 实际影响与预期安全边界。
- 已知缓解方式。

请勿在报告中附带无关的真实 Profile、Cookie、密码或用户文件。

## 处理与公告

维护者在私密报告内确认影响版本、部署前提和复现，区分产品边界与实际权限突破。需要补充材料时只索取最小复现，并保留报告者要求的署名方式；当前不承诺固定响应时限。

确认漏洞后，在受限修复分支处理代码、对应边界验证和必要迁移，协调报告者确定披露时间。修复发布说明列明受影响及已修复版本、影响、利用前提、升级步骤和可行缓解方式；不提供尚无修复且不利于用户防护的攻击细节。需要标准标识时通过 GitHub Security Advisory 申请 CVE，并将公告与正式 Release 相互链接。

若无法及时修复，应在私密报告中说明状态，准备实际可执行的关闭功能、撤销凭据或网络限制方案；不要把未经验证的措施称为修复。公开后跟踪遗漏的受影响版本并更正公告。最新支持版本以实际 Release 为准，不以未发布的候选版本号代替已发布修复。

## 安全边界

- Profile内的多个 Tab共享登录态；BrowShare不把它们声明为相互隔离的安全主体。
- Page Script和 Navigation Policy Script不能替代服务端授权。
- Viewer Ticket是短期、单用途凭证，不等于 Portal Session。
- Worker只主动连接控制面；CDP和 loopback服务不得暴露公网。
- Profile网页 Proxy与 Remote Tab信令/媒体链路必须分离。
- 本项目不承诺规避第三方网站的风控或服务条款限制。

目标网站改版、管理员错误配置、自托管主机失陷和用户主动共享凭据不自动构成本项目漏洞；如果这些条件能够突破本文档声明的权限边界，仍欢迎私密报告。
